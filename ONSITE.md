# Раздача на поляне: сайт ↔ сеть

Записка для того, кто делает точку доступа и сетевой обвес. Пишет её сторона
сайта. Ниже: что я отдаю, что от этого зависит, и что мне нужно от тебя.
Отвечать удобнее всего дописав свои ответы в конец этого же файла.

## Расклад

Сеть на фесте **автономная** — интернета наверх нет. Сверху точка доступа, под
ней тонкий клиент на Linux: на нём вся сеть и наш сайт. Гость подключается к
WiFi, у него всплывает заглушка (сонный мотылёк), он жмёт на лампу и попадает
на расписание.

## Что я отдаю

| что | где в репозитории | как раздавать |
|---|---|---|
| приложение с расписанием | корень | статикой как есть, **сборки нет** |
| заглушка каптива | `captive/index.html` | один файл, по http |
| сертификат | Let's Encrypt через DNS-01 | см. ниже |

Приложение — `index.html`, `app.js`, `core.js`, `map.js`, `styles.css`,
`sw.js`, `manifest.webmanifest` и каталоги `vendor/`, `data/`, `icons/`.
Никакого npm/webpack: `root` смотрит на корень репозитория, и всё.

Заглушка самодостаточна — **ни одного внешнего запроса**, даже звук
синтезируется на месте. На каптиве интернета ещё нет, любой CDN или шрифт
превратился бы в дырку.

## Четыре требования, на которых всё держится

**1. Сайт только по https, и http его отдавать не должен.**
Service worker, установка на «Домой» и избранное работают лишь в secure
context. `http://<ip>` под него не подпадает — исключение сделано только для
`localhost`. Если приложение окажется доступно и по http, часть гостей осядет
там и молча потеряет и установку, и избранное. На http-vhost — либо 301 на
https, либо 404, но не приложение.

**2. Заглушка остаётся на http, и это не лень.**
Пробы связи у телефонов ходят по http. Начнём перехватывать https — поймаем
ошибки сертификата на всём трафике. Значит каптив (http) и сайт (https) это
**разные origin**, и адрес сайта надо явно вписать в `CFG.url` в
`captive/index.html`. Страница его не угадывает и не пытается.

**3. Имя должно резолвиться локально.**
Апстрима у dnsmasq нет, поэтому без явной записи имя не разрешится вообще ни
у кого. Публичная A-запись на приватный IP (так делает Plex) — опционально,
пригодится только чтобы тестировать до выезда, пока интернет есть.

**4. `sw.js` нельзя долго кэшировать.**
С длинным `Cache-Control` браузер месяцами не заметит новую версию оболочки, и
гости застрянут на старой. Для `sw.js`, `index.html` и `data/program.json` —
`no-cache`. Остальное (`vendor/`, `icons/`) можно кэшировать спокойно.

## Наброски конфигов

Это эскиз, не готовый конфиг — подгони под себя, но смысл строк сохрани.

```nginx
# --- сайт: только https ---
server {
    listen 443 ssl;
    server_name raspisanie.example.ru;          # ← реальное имя

    ssl_certificate     /etc/letsencrypt/live/raspisanie.example.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/raspisanie.example.ru/privkey.pem;

    root /srv/insonmia;                          # корень репозитория как есть
    index index.html;

    # иначе новая версия оболочки не доедет до гостей
    location = /sw.js             { add_header Cache-Control "no-cache"; }
    location = /index.html        { add_header Cache-Control "no-cache"; }
    location = /data/program.json { add_header Cache-Control "no-cache"; }

    # nginx по умолчанию не знает этот тип, а без него манифест игнорируется
    location = /manifest.webmanifest { default_type application/manifest+json; }

    location /vendor/ { expires 30d; }
    location /icons/  { expires 30d; }
}

# --- http: заглушка и пробы; приложение НЕ отдаём ---
server {
    listen 80 default_server;
    server_name _;

    root /srv/insonmia/captive;
    index index.html;

    location = /generate_204    { return 204; }
    location = /connecttest.txt { default_type text/plain; return 200 "Microsoft Connect Test"; }
    location = /hotspot-detect.html {
        default_type text/html;
        return 200 "<HTML><HEAD><TITLE>Success</TITLE></HEAD><BODY>Success</BODY></HTML>";
    }
}
```

```conf
# dnsmasq: интернета нет, всё резолвим на себя
address=/raspisanie.example.ru/10.0.0.2

# домены проб связи — тоже на себя, отвечать на них будет nginx выше
address=/connectivitycheck.gstatic.com/10.0.0.2
address=/captive.apple.com/10.0.0.2
address=/www.msftconnecttest.com/10.0.0.2
```

## Пробы связи: логика двухтактная

Заглушка всплывает не потому, что сайт доступен, а потому, что у телефона
**не проходит проба связи**:

* Android — `connectivitycheck.gstatic.com/generate_204` (ждёт пустой 204)
* iOS/macOS — `captive.apple.com/hotspot-detect.html` (ждёт слово `Success`)
* Windows — `www.msftconnecttest.com/connecttest.txt`

Такты:

* **до авторизации** пробы должны *падать* — заворот на splash. Иначе телефон
  не поймёт, что попал в каптив, и окно не всплывёт вообще. Этим рулит
  каптив-демон, он перехватывает http неавторизованных клиентов независимо
  от DNS;
* **после авторизации** пробы должны *проходить* — иначе телефон будет
  ругаться «нет интернета», а iOS не закроет своё каптив-окно. Вот тут и
  срабатывают DNS-записи и `location`-ы из набросков выше.

Второй такт важнее, чем кажется: **каптив-окно iOS это урезанный вебвью, в нём
PWA не ставится**. Пока оно не закроется, гость не сможет открыть сайт
нормальным браузером и «положить на Домой» — то есть мы потеряем ровно то,
ради чего затевали https.

Хорошо бы объявить каптив честно — RFC 8910, DHCP-опция 114 с URL заглушки:
свежие iOS и Android понимают её и не гадают по пробам.

## Сертификат

Выпускать через **DNS-01** — проверка идёт TXT-записью, входящий интернет на
поляне не нужен:

```sh
certbot certonly --manual --preferred-challenges dns -d raspisanie.example.ru
```

Делать там, где интернет есть. **Живёт 90 дней** — выпустить незадолго до
выезда и глазами проверить, что срок перекрывает даты феста. Продлить на
поляне будет нечем.

## Что мне нужно от тебя

1. **Домен и имя сайта** — любой домен, где есть доступ к DNS (нужен для
   DNS-01). Без этого ни сертификата, ни `CFG.url`.
2. **IP тонкого клиента** в фестивальной сети — для записей dnsmasq.
3. **Какой каптив-демон** берёшь (opennds, nodogsplash, что-то своё) и
   **какой у него URL авторизации**. Это не праздный вопрос, см. ниже.
4. **Куда положишь репозиторий** — что писать в `root`.

### Про пункт 3 — тут есть подводный камень

Сейчас лампа на заглушке просто уводит на адрес сайта. Но если каптив-демон
до авторизации режет трафик, то:

* **https-хост надо занести в walled garden / preauth-allowlist**, иначе
  лампа уводит в таймаут — гость увидит бесконечную загрузку;
* и правильнее, чтобы тап по лампе **сначала дёргал URL авторизации демона**
  (у opennds это что-то вида `/opennds_auth/?tok=...`), и только потом
  уводил на сайт. Тогда пробы начнут проходить, каптив-окно закроется, и
  человек сможет открыть сайт нормальным браузером.

Скажи, какой демон и какой формат у его auth-URL — я допишу этот шаг в
заглушку. Сама по себе она угадать его не может.
